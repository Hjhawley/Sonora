├── core
│   ├── db
│   │   ├── mod.rs - SQLite boundary. Owns the Connection-backed Db type, DB opening, schema initialization, and submodule wiring for roots, reconciliation, track persistence, and small persisted app state.
│   │   ├── paths.rs - Resolves the platform-specific path to sonora.sqlite3 and ensures its parent directory exists.
│   │   ├── schema.rs - Creates the base SQLite schema, applies lightweight additive migrations, and creates required indexes once dependent columns exist.
│   │   ├── roots.rs - Persistent library-root management. Loads/adds/removes roots and deletes only track rows no longer covered by remaining roots.
│   │   ├── reconcile.rs - Scan-time reconciliation between discovered filesystem state and cached DB rows. Marks tracks under scanned roots missing until rediscovered, updates present/mtime/size facts, detects new/changed/backfill-needed files, and returns rows that must be rehydrated from disk.
│   │   └── tracks.rs - Track-row persistence and DB-backed library queries. Writes refreshed TrackRow metadata into cached columns, loads visible/hidden/missing rows directly from SQLite, maps SQL rows into TrackRows, and supports Sonora-only actions like hide/unhide/delete-from-Sonora.
│   ├── hydrate.rs - Metadata hydration pipeline. Turns DB-backed (TrackId, PathBuf) pairs into TrackRows by reading tags and probing media properties from disk. Used mainly during scan/save refreshes, not normal startup.
│   ├── library.rs - Read-only filesystem discovery. Finds candidate audio files and returns lightweight discovered-file records with path and basic file facts.
│   ├── load.rs - DB-backed TrackRow loading helpers. Loads cached visible, hidden, or missing rows directly from SQLite without rescanning the filesystem.
│   ├── mod.rs - Public core boundary. Exposes storage, scanning, hydration, playback, tags, and types, and re-exports the main helpers used by the GUI.
│   ├── playback
│   │   ├── decoder
│   │   │   ├── mod.rs - Opens an audio file with Symphonia, probes the default audio track, computes duration when possible, and builds the decoder source used by playback.
│   │   │   └── source.rs - Streaming Symphonia-backed decoder that exposes decoded audio as a rodio::Source.
│   │   ├── engine.rs - Playback transport and streaming engine. Owns the rodio sink and queue state, handles play/queue/pause/resume/stop/seek/volume commands, emits exact track-start/position/end events with monotonic playback IDs, and advances through queued sources until the queue is exhausted.
│   │   └── mod.rs - Public playback boundary. Defines the GUI-facing command/event API, exposes PlaybackController as a best-effort sender, and starts the playback engine thread while returning the event receiver the GUI polls.
│   ├── probe.rs - Probes read-only technical media properties such as duration, bitrate, sample rate, and channel count, using MP3-specific parsing with Symphonia fallback where needed.
│   ├── scan.rs - Core scan orchestration. Discovers candidate audio files under configured roots, de-dupes overlaps, reconciles discovered state into SQLite, hydrates only changed/new rows, persists refreshed metadata, and reloads the requested library scope from the DB.
│   ├── tags
│   │   ├── art.rs - Embedded MP3 artwork I/O. Reads preferred embedded artwork, writes replacement artwork as a single front-cover image, removes embedded picture frames when requested, and currently supports JPEG/PNG only. Artwork lives in file tags, not SQLite.
│   │   ├── mod.rs - Metadata backend boundary. Re-exports TrackRow read/write helpers, embedded-art helpers, and shared release-date helpers so higher layers depend on a small metadata API rather than ID3 details.
│   │   ├── read.rs - Reads and normalizes Sonora-managed ID3 metadata, merges it with probed technical properties, and constructs a TrackRow from the file.
│   │   ├── util.rs - Shared tag helpers such as slash-pair parsing, bool-ish parsing, counter decoding, and release-date normalization/extraction.
│   │   └── write.rs - Writes Sonora’s curated subset of TrackRow fields back into MP3 ID3 tags, replacing or removing frames Sonora manages while preserving unrelated existing tag data.
│   └── types.rs - Canonical app-level data model, especially TrackId and TrackRow. These types are shared across tags, DB caching, scan/load flows, GUI state, and query logic.
├── gui
│   ├── columns.rs - Shared Track View column model. Defines column identity, labels, default widths, sort-field mapping, and per-column UI state such as visibility and width.
│   ├── mod.rs - Top-level GUI boundary. Exposes state, theme, subscriptions, update logic, query logic, view logic, column model, and shared UI helpers, and re-exports the main entry points used by main.rs.
│   ├── query.rs - Pure Track View derivation layer. Handles search matching, full-table sorting across supported metadata columns, normalized query caches, and derived TrackId orderings for visible display order versus playback order.
│   ├── state.rs - Central shared GUI state. Defines the message enum, scope/view/playback enums, query state, Track View column configuration, selection state, playback UI state, caches, inspector state, artwork-edit state, and startup initialization of playback, saved roots/volume, cached library rows, and derived caches.
│   ├── subscription.rs - Application-level GUI subscriptions, including the periodic playback tick and global keyboard event listener.
│   ├── theme.rs - App-wide visual defaults such as the bundled font, forced dark theme, and custom palette for more consistent cross-platform styling.
│   ├── update
│   │   ├── actions.rs - DB-backed actions applied to the current selection. Performs hide, unhide, and delete-from-Sonora for the active scope, then reloads scope data and clears incompatible selection/inspector state.
│   │   ├── art.rs - Inspector artwork workflow and cover-loading helpers. Loads embedded artwork into UI image handles, manages choose/replace/remove/extract flows, stores pending artwork edits until save, and supports generic cover loading for tracks.
│   │   ├── inspector.rs - Inspector draft-state and mixed-selection logic. Updates draft fields, tracks structural mixed state, clears/resets inspector state when needed, and loads editable inspector data from the current selection.
│   │   ├── keyboard.rs - Global keyboard handling. Tracks modifier-key state and maps shortcuts to selection, playback, and save behavior.
│   │   ├── mod.rs - Routes incoming Message variants to the appropriate GUI update submodule.
│   │   ├── playback.rs - GUI-side playback bridge. Translates UI actions into playback-engine commands, defines queue policy for library vs album playback, manages shuffle/repeat/seek/volume UI state, and reacts to engine events. Library playback follows sort order but intentionally ignores search filtering.
│   │   ├── query.rs - Track View query-state transitions. Handles search changes and sort changes, including toggling direction when the current sort field is selected again, and resets virtualized scroll state when needed.
│   │   ├── roots.rs - Persistent library-root management from the GUI. Updates the root-path input, validates and de-duplicates added folders, writes changes through SQLite, and on removal reloads scope data and resets incompatible UI state.
│   │   ├── save.rs - Inspector save pipeline. Turns draft state into conservative tag writes, applies pending artwork edits, re-reads refreshed metadata from disk, and updates in-memory rows only after successful write + reread.
│   │   ├── scan.rs - GUI-side scan lifecycle. Starts the background scan task, maps the current GUI scope to the core scan/load scope, updates status text, and applies finished scan results back into Sonora state.
│   │   ├── scope.rs - Library-scope and view-mode transitions. Reloads the active DB-backed scope asynchronously, applies scope-load results back into Sonora state, resets incompatible selection/inspector state, and triggers album-cover preloading when needed.
│   │   ├── selection.rs - Track/album selection interactions and cover loading. Manages TrackId-based single/range/toggle selection, album-grid/detail interactions, double-click play behavior, album-track ordering for selection, and selection-driven cover loading.
│   │   └── util.rs - Small async helper for running blocking work off-thread and awaiting the result from GUI update flows.
│   ├── util.rs - Pure GUI helpers for fallback title generation, formatting, truncation, and parsing user input values.
│   └── view
│       ├── albums.rs - Renders Album View in two modes: album grid when no album is selected, and album detail when one is selected. Derives grid tiles from grouped album state, uses representative cached covers, sorts album tracks for detail display, and emits album/tile/header/track interaction messages.
│       ├── center.rs - Routes the center panel to Track View or Album View based on the current view mode.
│       ├── constants.rs - Shared layout and sizing constants for the window, sidebar, playback bar, editor, album grid, artwork, and the default Track View column widths consumed by the shared column model.
│       ├── inspector.rs - Renders the right-side tag editor, including mixed-state inputs, technical metadata, inspector artwork controls, and inspector action buttons.
│       ├── mod.rs - Top-level GUI renderer. Composes the sidebar, center panel, inspector, and playback bar into the full app layout.
│       ├── sidebar.rs - Renders the left sidebar with scan controls, scope controls, layout controls, action buttons, and root-folder controls.
│       ├── style.rs - Reusable widget styling helpers and shared UI colors for Sonora-specific buttons, table headers, row states, containers, and text inputs so the UI palette and control appearance stay consistent.
│       ├── tracks.rs - Renders Track View as a searchable, sortable, horizontally scrollable metadata table using derived visible TrackId order and shared per-column state from the Track View column model. Displays selection/now-playing markers, truncates overflowing text, and window-renders only the visible slice plus overscan.
│       └── widgets.rs - Reusable GUI widgets and helpers such as duration formatting, text truncation, cover thumbnails/placeholders, field-row builders, and the structured top playback bar.
└── main.rs - Bootstraps the Iced application, configures the window, applies the global theme/font, and wires together Sonora::default, update, view, and subscription through the GUI module.
