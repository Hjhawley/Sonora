├── core
│   ├── db
│   │   ├── mod.rs - Defines the SQLite DB boundary by owning the Connection-backed Db type, database opening, schema initialization, and submodule wiring for roots, reconciliation, track persistence, and small app-state persistence kept in SQLite for now.
│   │   ├── paths.rs - Returns the platform-specific path to sonora.sqlite3 and ensures its parent folder exists.
│   │   ├── schema.rs - Creates the base SQLite schema and applies lightweight additive migrations.
│   │   ├── roots.rs - Handles persistent library-root configuration and root-related cleanup. It loads/adds/removes library roots and deletes only track records no longer covered by remaining roots when a root is removed.
│   │   ├── reconcile.rs - Handles scan-time reconciliation between discovered filesystem state and SQLite track records. It marks tracks under scanned roots missing until rediscovered, updates present/mtime/size facts, detects new/changed/backfill-needed files, and returns the DB-backed rows whose metadata should be rehydrated from disk.
│   │   └── tracks.rs - Handles track-record persistence and DB-backed library queries. It writes refreshed TrackRow metadata into cached columns, loads visible/hidden/missing TrackRows directly from SQLite, maps SQL rows into TrackRows, and supports Sonora-only actions such as hide/unhide and delete-from-Sonora.
│   ├── hydrate.rs - Metadata hydration pipeline. It turns DB-backed (TrackId, PathBuf) pairs into TrackRows by reading tags and probed media properties from disk. Used mainly during scan/save refreshes rather than normal startup.
│   ├── library.rs - Performs read-only filesystem discovery and returns lightweight DiscoveredFile records containing path and basic file facts. It is the low-level file scanner used by core scan flows.
│   ├── load.rs - DB-backed TrackRow loading helpers. It loads cached visible, hidden, or missing library rows directly from SQLite without rescanning the filesystem, which keeps startup and scope switches fast.
│   ├── mod.rs - Defines the public core boundary. It exposes storage, scanning, hydration, playback, tag, and type modules, and re-exports the main high-level helpers the GUI uses for scan flows and DB-backed library loads.
│   ├── playback
│   │   ├── decoder
│   │   │   ├── mod.rs - Opens an audio file with Symphonia, probes the default audio track, computes duration when possible, and constructs the decoder source used by the playback engine.
│   │   │   └── source.rs - Implements the streaming Symphonia-backed decoder that exposes decoded audio as a rodio::Source for playback.
│   │   ├── engine.rs - Playback transport and streaming engine. It owns the rodio sink and queue state, handles play/queue/pause/resume/stop/seek/volume/shutdown commands, emits exact track-start/position/end events with monotonic playback IDs, and advances through queued sources until the queue is exhausted.
│   │   └── mod.rs - Public playback boundary. It defines the command/event API shared with the GUI, exposes PlaybackController as a best-effort command sender, and starts the playback engine on its own thread while returning the event receiver the GUI polls.
│   ├── probe.rs - Probes read-only technical media properties such as duration, bitrate, sample rate, and channel count, using MP3-specific parsing with Symphonia fallback where needed.
│   ├── scan.rs - Core scan orchestration. It discovers candidate audio files under the configured roots, de-dupes overlapping results, reconciles discovered state into SQLite, hydrates metadata only for changed/new rows, persists refreshed metadata, and reloads the requested library scope from the DB.
│   ├── tags
│   │   ├── art.rs - Embedded MP3 artwork IO layer. It reads the preferred embedded image by preferring front cover art and falling back to the first picture, writes replacement artwork as a single front-cover image, removes all embedded picture frames when requested, and currently supports JPEG/PNG only. Artwork lives in file tags, not SQLite.
│   │   ├── mod.rs - Metadata backend boundary. It keeps the public metadata IO surface intentionally small by re-exporting TrackRow read/write helpers, embedded-art helpers, and shared release-date normalization helpers, so higher layers depend on a format-agnostic metadata API rather than ID3 details.
│   │   ├── read.rs - Reads and normalizes ID3 metadata, merges it with probed technical properties, and constructs a TrackRow from Sonora’s combined tag/probe view of the file.
│   │   ├── util.rs - Provides shared tag-parsing helpers such as slash-pair parsing, bool-ish parsing, counter decoding, and release-date normalization/extraction.
│   │   └── write.rs - Writes Sonora’s curated subset of TrackRow fields back into MP3 ID3 tags, replacing or removing the frames Sonora manages and normalizing Sonora’s write policy for fields like comments, lyrics, and release date.
│   └── types.rs - Defines Sonora’s canonical app-level data model, especially TrackId and TrackRow. These types flow through the tag layer, DB cache, GUI state, query logic, and rendering code.
├── gui
│   ├── mod.rs - Defines the top-level GUI boundary, exposing state, subscriptions, update logic, query logic, view logic, and UI helpers. It re-exports the main entry points used by main.rs.
│   ├── query.rs - Pure derivation layer for Track View. It handles search matching, sorting, normalized query caches, and derived TrackId orderings for visible display order versus playback order.
│   ├── state.rs - Defines Sonora’s central shared GUI state, including the message enum, scope/view/playback enums, query state, selection state, playback UI state, caches, inspector draft state, artwork-edit state, and startup restore behavior. It is data-centric and intentionally avoids view/update logic.
│   ├── subscription.rs - Creates application-level GUI subscriptions, including the periodic playback tick and global keyboard event listener.
│   ├── update
│   │   ├── actions.rs - Handles DB-backed actions applied to the current selection. It performs hide, unhide, and delete-from-Sonora operations for the appropriate scopes, then reloads the active scope and clears selection/inspector state.
│   │   ├── art.rs - Inspector artwork workflow and cover-loading helpers. It loads embedded artwork into UI image handles, manages choose/replace/remove/extract flows through native file dialogs, stores pending artwork edits in inspector state until save, and supports generic cover loading for tracks.
│   │   ├── inspector.rs - Inspector draft-state and mixed-selection logic. It updates draft fields, tracks per-field mixed state structurally, clears/reset inspector state when needed, and loads single- or multi-selection metadata into the editable inspector from selected TrackIds.
│   │   ├── keyboard.rs - Handles global keyboard events, tracks modifier-key state, and maps shortcuts to selection, playback, and save behavior.
│   │   ├── mod.rs - Routes incoming Message variants to the appropriate GUI update submodule.
│   │   ├── playback.rs - GUI-side playback controller and engine bridge. It translates UI actions into playback-engine commands, defines queue policy for library vs album playback, manages shuffle/repeat/seek/volume UI state, and reacts to engine events. Library playback follows track sort order but intentionally ignores search filtering.
│   │   ├── query.rs - Handles Track View query state transitions such as search changes, clearing search, changing sort fields, and toggling sort direction. It also resets virtualized Track View scroll state when needed.
│   │   ├── roots.rs - Handles persistent library-root management. It updates the root-path input, validates and de-duplicates added folders before writing them through to SQLite, and on removal deletes only track records no longer covered by remaining roots, reloads the active scope from the DB, and resets selection/inspector state.
│   │   ├── save.rs - Handles inspector saves by turning draft state into conservative tag writes, applying pending artwork edits, re-reading refreshed metadata from disk, and updating in-memory rows only after successful write + reread.
│   │   ├── scan.rs - GUI-side scan lifecycle. It starts the background scan task, maps the current GUI scope to the core scan/load scope, updates status text, and applies finished scan results back into Sonora state.
│   │   ├── scope.rs - Handles library-scope and view-mode transitions. It asynchronously reloads the active DB-backed scope, applies scope-load results back into Sonora state, resets incompatible selection/inspector state, and triggers album-cover preloading when needed.
│   │   ├── selection.rs - Handles track/album selection interactions and selection-driven cover loading. It manages stable TrackId-based single/range/toggle selection, album-grid/detail interactions, double-click play affordances, album-track ordering for selection, and cover loading for selected tracks and album representatives.
│   │   └── util.rs - Provides a small async helper for running blocking work off-thread and awaiting the result from GUI update flows.
│   ├── util.rs - Contains pure GUI helpers for fallback title generation, formatting, and parsing user input values.
│   └── view
│       ├── albums.rs - Renders Album View in two modes: an album grid when no album is selected, and an album detail screen when one is selected. It derives grid tiles from grouped album state, uses representative cached covers, sorts album tracks for detail display, and emits album/tile/header/track interaction messages.
│       ├── center.rs - Routes the center panel to either Track View or Album View based on the current view mode.
│       ├── constants.rs - Defines shared layout and sizing constants for the window, sidebar, playback bar, editor, track rows, album grid, and artwork.
│       ├── inspector.rs - Renders the right-side tag editor, including mixed-state inputs, technical metadata, and inspector artwork controls.
│       ├── mod.rs - Acts as the top-level GUI renderer, composing the sidebar, center panel, inspector, and playback bar into the full app layout.
│       ├── sidebar.rs - Renders the left sidebar with scan controls, scope/view controls, hide/unhide actions, and root-folder controls.
│       ├── tracks.rs - Renders Track View as a searchable, sortable table list using derived visible TrackId order rather than raw Vec order. It uses stable id-based row interactions, displays current selection/now-playing markers, and window-renders only the visible slice plus overscan based on scroll/viewport state.
│       └── widgets.rs - Provides reusable GUI widgets and helpers such as duration formatting, cover thumbnails/placeholders, field-row builders, and the top playback bar.
└── main.rs - Bootstraps the Iced application, configures the window, and wires together Sonora::default, update, view, and subscription through the GUI module.
